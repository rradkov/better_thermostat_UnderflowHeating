# 1.9.3.1.6 — Warm Floor release

This release promotes the user-confirmed Warm Floor development state to
production. Experimental post-window Boost on a secondary climate device is
suspended while further development continues on `dev`.

## Added

- Adaptive Warm Floor maintenance uses available outdoor and water temperature,
  room trends, and learned thermal load information.
- Auto policy and diagnostic status make maintenance decisions and actuator
  phases visible without assuming a particular heat source or installation.

## Changed and fixed

- Warm Floor maintenance balances room target proximity, cooling trends, and
  residual warming; below-target heating remains owned by normal room control.
- Generic Thermostat duty phases respect actuator travel time and preserve
  maintenance eligibility at the exact target temperature.
- Stale maintenance commands are released when appropriate; heater recovery,
  periodic ticks, and the liveness watchdog keep control progressing.
- Warm Floor diagnostics reflect unavailable heaters and consistent decisions.
- Remove a duplicated control pass so initialization guards, shared-device
  ownership, and paced retries apply consistently to every control cycle.
- Manifest, project, and lockfile versions are synchronized. The documented Home
  Assistant requirement matches the existing dependency and HACS minimum.
- Automated checks run on `dev` and `main`, replacing obsolete branch names.

## Suspended

- Secondary-device Boost settings, its manual `better_thermostat.test_boost`
  service, its status sensor, and its automatic window/control-loop hooks are
  disabled in this production release.
- Previously saved enabled Boost settings cannot bypass the production block.
- The implementation and its tests are retained for development. The ordinary
  Boost temperature preset, normal secondary-device cooling, and Warm Floor
  remain available.

## Compatibility and upgrade

- Requires Home Assistant **2026.9.0 or later** and its supported Python runtime.
- Update through HACS or replace the integration files, then restart Home
  Assistant so the production feature policy and service registration reload.
- Existing Warm Floor configuration is retained. Secondary-device Boost is
  unavailable even if it was previously enabled; automations calling its test
  service must be disabled or revised.
- No automatic control of heat-source flow temperature or heating-curve offset
  is introduced in this release.

## Verification

The maintainer confirmed the current Warm Floor behavior in their installation.
Release verification additionally covers production Boost isolation, retained
development Boost tests, Warm Floor regressions, release metadata, source
formatting, and automated repository checks. Detailed results are recorded in
the GitHub release notes.
